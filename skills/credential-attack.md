# 凭据获取与复用

> 红线：**只有凭据不算拿到账号**。必须实际登录成功（浏览器/客户端/协议）才记账号权限。
> 自己注册或自建的账号不算得分，只留痕。

## 1. 低风险来源（优先）

| 来源 | 做法 |
|---|---|
| 配置泄露 | `.git/config`、`.env`、`config.php.bak`、备份包里的连接串 |
| 前端硬编码 | JS 里的 AK/SK、`password=`、测试账号注释 |
| 日志/错误页 | 堆栈里打印的 DB 连接串、内网地址 |
| 公开代码仓库 | 搜主域/公司名的 key（GitHub / Gitee） |
| 弱口令 | 中间件默认口令、管理后台常见组合（**控制次数**） |

## 2. 弱口令（有度）

```bash
# 只对授权范围内的服务做，单账号失败 3 次即停
hydra -L users.txt -P pass.txt -t 4 -f ssh://<target>
```

- 优先试中间件默认口令（Nacos/Tomcat/Weblogic/Redis 未授权）
- 达到锁定阈值前必须停：锁定账号会打草惊蛇
- 生产环境一律先问用户是否允许爆破

## 3. 凭据复用

拿到一组口令后，在所有已收集资产上**小批量**验证：

1. 同一套口令试同域其它系统（SSO/运维平台最常见）
2. 相同用户名模式（`admin`/`test`/`ops`）跨系统试
3. **每条都记录**：来源系统 → 命中系统 → 是否成功

## 4. 落库与升级

```
redteam_credential_add({ assetId, username, secretMasked })
```

- `secretMasked` 只存脱敏形式（`ad***n` / `sk-****`），完整口令不要落盘
- 登录成功后调 `redteam_evidence_upgrade`，`verifiedResult` 写"用什么客户端、看到什么页面"
- 才算「账号权限」得分，再到 `redteam_score_hit`

## 5. 判定标准

- [ ] 每条凭据都有来源（哪个资产、哪个文件/接口）
- [ ] 声称"拿到账号"的，必须有登录成功证据（截图描述 / 后台首页标题 / API 返回）
- [ ] 脱敏已做，库里没有明文口令
- [ ] 未成功的复用尝试也有记录（避免重复劳动）

## 常见坑

| 坑 | 处理 |
|---|---|
| 有 hash 就报"拿下了" | 必须破解/复用登录成功 |
| 自建账号充数 | 只留痕，不计分 |
| 爆破把账号锁死 | 控制次数，优先默认口令 |
| 明文口令写进库 | 一律脱敏 |
