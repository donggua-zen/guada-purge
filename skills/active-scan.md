# 主动扫描

> 主动 = 向目标发包。**必然留痕**，所以节奏和顺序比工具有多强更重要。

## 顺序（由轻到重）

```
1. 少量端口探活（top100）      → 确认哪些主机活着
2. 全端口（仅对存活主机）      → nmap -p- --min-rate 2000
3. 服务与版本                → nmap -sV -sC
4. Web 指纹                  → 见 web-fingerprint
5. 漏洞模板                  → 见 nuclei-scan
6. 目录爆破                  → 见 dir-bruteforce（最吵，放最后）
```

## 限速（硬要求）

```bash
# 存活判断：快但克制
nmap -sn 10.0.0.0/24 --min-rate 500

# 全端口：只对已确认存活的主机
nmap -p- --min-rate 2000 -T4 -oA full 10.0.0.5

# 服务识别：降速避免触发 IDS
nmap -sV -sC -p 22,80,443,3306,6379,8080 --max-rate 300 10.0.0.5
```

生产/授权目标一律：`--max-rate ≤ 300`，`nuclei -rate-limit ≤ 50`。

## 什么时候必须停

- 返回码突变（403/429 激增）
- 目标响应时间从 50ms 涨到 2s+
- 出现验证码 / 封禁页
- 用户明确要求暂停

## 落库

存活主机 + 开放端口 + 服务版本 → `redteam_asset_add`（`kind=host` / `service`）
扫描日志 → 可选 `redteam_attack_file_add`

## 判定标准

- [ ] 只对存活主机做全端口（不要整段扫）
- [ ] 每个开放端口有服务与版本
- [ ] 扫描日志留档（报告要引用）

## 常见坑

| 坑 | 处理 |
|---|---|
| 一上来就全端口扫整段 | 先探活，再定向 |
| 无限速 → 打挂服务 | 设 `--max-rate` |
| 只扫 TCP | 别忘了 UDP 关键服务（161/123/500） |
| 被 WAF 封了还硬扫 | 换时间窗或换源 IP |
