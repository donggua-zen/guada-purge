# 目录与接口发现

> 最吵的一步，放最后做。目的不是"扫出多少条"，而是**找到没在首页暴露的入口**。

## 工具与节奏

```bash
# 先小字典快速过一遍
ffuf -u https://target/FUZZ -w common.txt -mc 200,204,301,302,401,403 -t 20 -rate 50

# 命中后再上大字典，只打特定前缀
ffuf -u https://target/admin/FUZZ -w big.txt -mc all -t 10 -rate 30
```

feroxbuster / dirsearch 同理，关键参数是 `-t`（并发）和 `-rate`（每秒请求）。

## 状态码判读

| 码 | 含义 | 是否值得跟进 |
|---|---|---|
| 200 | 存在且可访问 | ✅ 立刻看内容 |
| 204 | 存在但无内容 | ✅ 常是 API 端点 |
| 301/302 | 跳转 | ✅ 看跳到哪（常是登录页/目录） |
| 401 | 需要认证 | ✅ 值得试弱口令/绕认证 |
| 403 | 禁止访问 | ⚠️ 看是否能用 `..;/`、`%2e`、大小写绕过 |
| 500 | 服务端错误 | ✅ 可能是参数缺失导致的报错，有注入嫌疑 |
| 404 | 不存在 | ❌ 除非是软 404（返回 200 但内容是 404 页） |

**软 404 处理**：先请求一个随机路径，看它返回什么。相同特征的一律过滤。

## 落库

发现的路径 → `redteam_asset_add`（`kind=url`，`surface` 写"后台登录页/备份文件/API"）
可访问的敏感文件（`.git`、`.env`、备份包）→ 直接 `redteam_vuln_add`

## 判定标准

- [ ] 已排除软 404
- [ ] 命中的每条都实际打开看过（不是只看状态码）
- [ ] 敏感文件已单独记为漏洞

## 常见坑

| 坑 | 处理 |
|---|---|
| 软 404 当命中 → 几百条垃圾 | 先测随机路径基线 |
| 不限速 → 封 IP | `-rate` 必设 |
| 字典太大跑几小时 | 先小字典找方向，再定向大字典 |
| 只扫根目录 | 先摸清应用结构，再对每个模块扫 |
