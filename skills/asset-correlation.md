# 资产关联

> 单个资产的价值有限，**关联**才出机会：同一个 IP 上的多个站点、同一套系统的主站与后台、
> 泄露的凭据能登哪个系统。

## 常见关联关系

| 关系 | 判定方式 | `redteam_asset_link` kind |
|---|---|---|
| 主域 → 子域 | crt.sh / 备案 / 命名规律 | `subdomain` |
| 域名 → IP | DNS 解析 / 被动 DNS | `resolves-to` |
| IP → 站点 | 反查绑定域名（FOFA `ip=`） | `hosts` |
| 站点 → 后台/接口 | 路径发现、robots、JS 里的 API 前缀 | `related` |
| 入口 → 内网 | 隧道可达网段 | `pivot` |

## 操作

1. `redteam_asset_graph` 看现有节点与边
2. 找到孤岛资产（没有边的）→ 优先补它与其他资产的关系
3. 重点找三类"顺藤"：
   - **同 IP 多站点**（一台机器一个漏洞 = 多个站点全中）
   - **主站与后台同一套代码**（后台入口可能未授权）
   - **泄露的 AK/SK 能登哪个云/哪个系统**
4. 每建立一条关系就 `redteam_asset_link`

## 判定标准

- [ ] 每个"孤岛"资产都有至少一条边，或者标注为什么孤立
- [ ] 同 IP 的多站点已合并成一组
- [ ] 有至少一条"从外到内"的 pivot 关系（如果已经打通）

## 常见坑

| 坑 | 处理 |
|---|---|
| 只记资产不记关系 | 报告里就变成流水账 |
| 认为同 IP 一定是同一系统 | 虚拟主机可能完全不同 |
| 忽略 JS 里的接口前缀 | 那是最常见的未授权入口 |
